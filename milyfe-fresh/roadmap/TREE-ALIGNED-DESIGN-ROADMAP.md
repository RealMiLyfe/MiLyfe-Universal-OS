# MiLyfe Tree-Aligned Design Roadmap

**Status:** Design phase roadmap
**Rule:** No rushed implementation. Each phase produces reviewed Markdown design, contracts, decisions, and acceptance evidence before the next phase begins.

## Phase 0 — Tree lock

Deliver:

- Roots definition
- Trunk definition
- Governance Branch definition
- Lifestyle Branch definition
- Finance Branch definition
- Exactly four primary OSes per branch
- Supporting-OS classification
- No-new-branch rule

Exit gate: human approval that the tree is the stable architecture.

## Phase 1 — Roots and constitutional foundation

Deliver:

- MiLyfe Constitution
- Commons Charter
- Mi Being Charter
- Ratification and amendment procedure
- Rights and responsibility map
- Human/AI authority rules
- External-law boundary
- Constitutional terminology review

Exit gate: roots are coherent, reviewable, and cannot be silently overridden by a branch.

## Phase 2 — Trunk boundary design

Deliver:

- Kernel boundary
- Identity and naming
- Onboarding
- Data spaces
- Presence and continuity
- MiPsyche relationship to the trunk
- Agent and device boundary
- Security
- Development and operations
- Communication
- Scaling
- Trunk-to-branch interface

Exit gate: every trunk component has one responsibility and every branch knows what it receives from the trunk.

## Phase 3 — Shared contract freeze

Deliver:

- API contracts
- Event contracts
- Receipt contracts
- Permission contracts
- Data-space contracts
- Export/deletion contract
- Agent skill contract
- Device workload contract
- MiPsyche continuity contract
- Money-state contract
- Branch handoff contract
- Versioning and compatibility rules

Exit gate: no primary branch OS is designed without registered interfaces.

## Phase 4 — Governance Branch design

Deliver:

- Governance OS charter
- MiLegal charter
- MiResolve case lifecycle
- MiJustice rights and evidence lifecycle
- Authority matrix
- Due process
- Appeals
- Human support
- Campaign/election/public-office separation
- Governance security and privacy

Exit gate: people can understand how decisions, disputes, legal matters, and rights protection work.

## Phase 5 — Lifestyle Branch design

Deliver:

- MiCare charter
- MiHealth boundary
- MiPlace local-service model
- MiEducation learning and credential model
- Sensitive-data rules
- Professional and emergency boundaries
- Accessibility
- Child and vulnerable-person protections
- Lifestyle support and escalation

Exit gate: the branch improves real daily life without overclaiming professional authority or exposing sensitive data.

## Phase 6 — Finance Branch design

Deliver:

- MiForge venture lifecycle
- MiMarket marketplace lifecycle
- MiMoney ledger and settlement model
- MiWork contribution and livelihood model
- Business and merchant onboarding
- Fees, refunds, disputes, and support
- Projected versus settled value
- Reserves and treasury
- Device and agent contribution value
- USD/`$MLY` activation gates

Exit gate: the branch creates and circulates value without fake balances, hidden fees, unverified rewards, or unsupported financial claims.

## Phase 7 — Cross-branch design

Deliver:

- Person journey
- Household journey
- Business journey
- Worker journey
- Care journey
- Dispute journey
- Marketplace journey
- Education-to-work journey
- Branch data handoffs
- Cross-branch permissions
- Cross-branch receipts
- Cross-branch failure and rollback

Exit gate: the branches work together without merging their authorities.

## Phase 8 — Brand, public documents, and legal review

Deliver:

- Brand kit
- Production asset specification
- Founder story
- White paper
- Architecture blueprint
- Public terms
- Privacy notice
- Accessibility statement
- AI policy
- Device terms
- Marketplace and business terms
- `$MLY` disclosure
- Campaign disclosure
- U.S. legal review
- U.S. financial review

Exit gate: public claims are accurate, sourced, owned, accessible, and reviewed.

## Phase 9 — Security, agent, and release design

Deliver:

- Threat model
- Data-flow maps
- Access and secret policy
- Agent roles and skills
- Prompt-injection defense
- Security test matrix
- Incident response
- Backup and disaster recovery
- SBOM and build provenance
- Release workflow
- Rollback
- Evidence register

Exit gate: the future build can be tested, published, monitored, and rolled back safely.

## Phase 10 — Build readiness review

Deliver:

- Complete document register
- Owner and steward assignments
- Approved ADRs
- Contract registry
- Active-risk review
- GitHub repository plan
- First vertical slice plan
- Synthetic-data plan
- Pilot scope
- Locked-capability register

Exit gate: human approval to leave design phase.

## Phase 11 — Implementation begins

Only after Phase 10:

- Repository bootstrap
- Kernel vertical slice
- MiOnboard
- Trunk contracts
- First branch slice
- Tests and security evidence

The implementation phase starts with the trunk and one small vertical slice, not the entire platform at once.
