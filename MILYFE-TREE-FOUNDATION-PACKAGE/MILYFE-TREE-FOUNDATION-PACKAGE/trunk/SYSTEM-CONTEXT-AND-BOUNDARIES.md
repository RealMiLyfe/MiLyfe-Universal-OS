# MiLyfe System Context and Boundaries

**Status:** Architecture design

## Inside MiLyfe

- Kernel
- Cells
- Identity
- Data spaces
- OS registry
- Receipts and events
- MiOnboard
- MiPsyche
- MiMind
- MiAgent
- MiDevice
- MiMarket
- MiForge
- MiMoney
- MiScale
- MiSecurity
- MiDev
- MiOps
- Governance
- Legal, justice, care, place, campaign, and public-office profiles

## Outside MiLyfe

- External payment providers
- Banks and financial institutions
- Government agencies
- Courts
- Election authorities
- Licensed professionals
- GitHub or self-hosted Git forges
- Cloud and infrastructure vendors
- External software projects
- Insurance providers
- Tax authorities
- Public media and social networks

## Boundary rule

External systems connect through explicit adapters with terms, permissions, provenance, failure handling, and exit behavior. No external vendor silently becomes the authority for Kernel, `$MLY`, governance, MiPsyche, or public-office records.
